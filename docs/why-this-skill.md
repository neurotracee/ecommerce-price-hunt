# 设计说明：为什么把「比价」写成一份 Skill

本项目是为 [DSH go](https://github.com/ccch1mneyyy/dsh-go/) 做的附属功能开源项目。它不增加任何新的模型能力，也不调用任何新的接口——它做的是**在既有 Agent 能力之上加约束**，把一次比价任务从「自由发挥」变成「按闸门走」。

## 1. 比价任务的失败，大多不是能力问题

让 Agent 自己去比价，通常不会「做不到」，而是会**返工**：

- 第一轮报了「最低价」，第二轮发现那是首屏广告位不同规格的商品；
- 用标价排序，交完报告才发现没算运费和券门槛；
- 药品任务里混进了妆字号的同名洗剂，整张表不能用；
- 为了确认规格，把所有平台的详情页又重读一遍；
- 每次都重新设计 HTML 报告的章节与配色，截图检查反复不通过。

每一次返工都意味着：重新读屏、重新读图、重新组织上下文、重新生成报告。**token 与时间主要消耗在返工上，而不是采集上。** 所以本项目的切入点是「一次做对」，而不是「做得更快」。

## 2. 四个设计支点

### 闸门前置（gate first）

`SKILL.md` 的第 0 步先判品类，再决定用哪套规则。药品任务在搜第一个平台之前就已经锁定了「只认国药准字 + OTC/RX」和排除清单。把约束放在最前面，可以避免整轮采集作废——这是整套设计里性价比最高的一条。

同理的还有：先看应用清单确认入口（闪购 App ≠ 综合电商）、先确认规格再算单价、先算实付再排序。

### 口径唯一（one definition）

单价、实付、券门槛、风险标签全部在 `references/pricing-method.md` 里给出唯一定义。Agent 不需要临场决定「这次要不要含运费」，也就不会出现同一份报告里两套口径。

### 按需加载（load on demand）

四份手册总共约一万字，全部塞进上下文既贵又容易淹没关键规则。`SKILL.md` 用一张表把「场景 → 必读文件」写死：

| 场景 | 只读 |
| --- | --- |
| 首次做某平台 | `platform-playbooks.md` |
| 读不到屏幕、误点、页面是图 | `screen-reading.md` |
| 换算、券与运费 | `pricing-method.md` |
| 写报告 | `report-spec.md`（+ 宿主 HTML 技能） |

入口文件本身保持精简，长手册只在触发时加载。

### 结构固定（fixed output）

`references/report-spec.md` 定死 10 个章节与清单列定义，`assets/report-skeleton.html` 给出可复用的骨架。报告不再每轮重新设计，双屏自检也变成一张固定清单。

## 3. 关于「减少 token 与时间」

**我们只做机制上的说明，不做数值承诺。** 可归因的机制是：

1. 上下文里只放当前需要的手册（按需加载）；
2. 因口径/规格/品类错误导致的整轮返工被前置闸门拦掉；
3. 报告结构与自检清单固定，减少多轮「改版式 → 重截图」；
4. 「读不到就写局限、不猜」减少为圆一个幻觉而追加的检索与追问。

不同模型、不同设备、不同平台的可达性差异很大，任何「节省 X%」的数字都不可移植，因此本项目不提供这类基准，也不接受以效果数字为卖点的 PR（见 `CONTRIBUTING.md`）。

## 4. 为什么不写成自动化脚本

因为那样会立刻跨过本项目的边界：

- 平台协议与风控：批量/高频访问需要绕过机制，本项目明确禁止绕过；
- 活动价与大促标签：很多只存在于真实 UI 的渲染层，接口拿不到；
- 合规风险：药品比价尤其不能变成对外数据服务。

代价是慢、强依赖设备状态、平台改版要跟着更新手册。这是**有意接受**的取舍，写在 `README.md` 的「设计取舍」里。

## 5. 为什么不绑定 DSH go 的本地路径

原始 Skill 里引用了 `~/.dsh/skills/html/SKILL.md` 这类宿主专属路径。开源之后，它应当能被任意具备读屏能力的 Agent 复用。因此：

- 报告样式与双屏自检**优先**复用宿主 HTML 技能；
- 没有该技能时，按 `references/report-spec.md` 的断点与自检清单自行实现；
- 具体映射见 [portability.md](portability.md)。

上游仓库：<https://github.com/ccch1mneyyy/dsh-go/>。本项目不是其官方组件，也不含其代码。

## 6. 一句总结

> 把踩过的坑写成闸门，把口径写成唯一定义，把长手册拆成按需加载，把输出写成固定模板。
> 剩下的，交给 Agent 的读屏能力。
