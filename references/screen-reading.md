# 读屏与操作：踩过的坑与快手打法

本场实测（安卓无障碍 + 各电商 App）总结。目的是少走弯路：先按「快路」走，卡住再按「坑」对照。

## 快路（默认顺序）
1. **先读树，不读图**：`screen` 无图先看一次；元素带文字且能点就用编号点，比坐标稳。
2. **列表要滚**：`scroll(screen, direction)` 指定列表编号（屏幕上会标「列表 [n] 可下滑」）；一屏读不到就继续滚，每平台 3–5 屏。
3. **排序与筛选优先点按钮，不靠肉眼扫**：价格排序、销量排序、筛选面板都在顶部一行，点一次省十次滚动。
4. **筛选面板往往是纯文本**：WebView/图片型页面的正文读不到，但点开「筛选」后弹出的原生面板常常完整可读（价格区间、发货地、服务标签都在里面）——**用它当读数入口**。
5. **详情页继续滚**：规格/容量/克数常写在图片或规格选项里，滚到底再判断。
6. **兜底进结算页**：详情页仍无价格/规格 → 点右下角「购买/立即购买/去支付」，那里有商品名、款式、规格、运费与实付；看到为止，不提交。
7. **要证据就截图**：`screen(image:true)` 拿标号截图，人工读数；需要点图内区域才用 `tap_xy`。

## 坑与对策
| 现象 | 原因 | 对策 |
| --- | --- | --- |
| 「屏幕编号已过期 / 坐标对不上」 | 每次动作都产生新屏幕，编号与截图都会失效 | 动作后先 `screen` 再点；坐标必须来自最近一次带图截图 |
| 无障碍树只有 1 个「Web 视图」 | Edge 等浏览器不暴露网页正文 | 立刻转截图读数；或改用 App 原生页/筛选面板 |
| 整页只有下划线与占位符 | 页面用图片渲染（详情页、图文描述） | 截图读数；逐段滚动，一次只截一屏 |
| 首屏空白、只有骨架/广告 | 页面还在加载或开屏广告 | 再读一次；广告找右上角或底部关闭按钮 |
| 价格读成「¥ 8 . 3」多段 | 无障碍把价格拆成文本节点 | 按顺序拼接；别只看整数部分，注意 `.30` 与 `.3` |
| 标题被截断成「某某 120g…」 | 卡片标题用省略号 | 规格与品牌必须进详情页确认，不靠标题下单 |
| 误点赞、误关注、误加购 | 视频流/卡片区域太大，点了内容区 | 只用带文字的按钮编号点；内容区一律不点 |
| 点 tab 没反应 | 点在图标而非文字上 | 优先点「文本 xxx 按钮」元素；确认树里状态变为「已选中」 |
| 应用锁/面容验证挡住 | 抖音、快手等有安全中心锁 | 立即 `handoff` 请用户解锁，别尝试绕过 |
| 药品详情页弹「安全窗口、禁止截屏」 | 平台风控页 | 返回上一页重进或换一家店；不要反复触发 |
| 机器人客服答非所问 | 先回模板 | 追问具体问题（发货地/快递/几天到），等人工；记录原话 |
| 网页版没有客服入口 | 「仅支持客户端购买」 | 报告里如实写「无法在线咨询」，不编造答复 |
| 滚动一下只挪一点 | 惯性滚动步长小 | 连续滚 2–4 次再读，别指望一次到页底 |
| 排序按钮名不统一 | 京东「价格」点一下才变「从低到高」；淘宝没有价格 tab | 点完确认按钮文案变化；没有就改用价格区间筛选 |

## 效率技巧
- 同一平台的一批商品先「排序 + 筛选」定位价格带，再只对前 3 名进详情页，别逐条点。
- 一次截图里能读到 4 个商品就够；读不完就滚，别反复点进去。
- 每个平台记下「在售条数、价格带、活动标签、排序方式」再走，报告里能直接复用。
- 数量少（只有 2–3 条）要如实说明「这个平台就这么多」，不要拿别的平台数据补。
- 时间戳与活动条件一起记：大促到手价按小时变，报告里必须写采集时刻。

## 数据落地格式
```
平台 | 店铺 | 商品名 | 规格 | 标价 | 实付 | 单价(元/g) | 销量 | 标签 | 采集时间
```
先落这张表，再写报告；缺字段的格子留空并在局限里说明，不猜。
