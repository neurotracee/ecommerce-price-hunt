# 触发话术示例

> 以下全部为**话术模板**，不含真实品牌、真实商品、真实价格或真实店铺。尖括号 `〈〉` 表示需要使用者自己填写。

## 会触发本 Skill 的说法

- 「开始针对〈品牌 商品名 规格〉做全网比价，出 HTML 报告，我收货地在〈省 市〉。」
- 「到各大电商平台看看〈商品〉哪个最划算，按到手价和单价排。」
- 「查一下〈药品通用名〉各平台多少钱，只看药，不要妆字号。」
- 「同一款〈商品〉在几个平台比一下，最低价前三名帮我看发货地和几天到。」
- 「帮我做一份〈商品〉的比价 HTML 报告，标清楚券门槛和运费。」

## 带约束的说法（约束会被当成硬条件）

- 「只看前 3 名深挖，其余列表就行。」→ 只深挖前 3，其余仅列表。
- 「只要 OTC，不看 RX。」→ 药品闸门收紧；用户没点名时默认只报 OTC。
- 「不要妆字号 / 不要洗护类的。」→ 排除项升级为硬约束，宁可少报也不混入。
- 「我只有网页版，没有 App。」→ 报告需写明「网页版读数、无 App 客服」。
- 「限 3 个平台以内。」→ 遵守单次任务 ≤3 个平台深挖的建议。

## 会触发「交还用户」的说法（Agent 应停下，不自行处理）

- 「帮我登录一下 / 收一下验证码。」
- 「这个 App 有应用锁，你绕过看看。」
- 「直接替我下单付款。」

正确行为：停止并请使用者本人完成；结算页最多读到价格为止。

## 不该对本项目提出的要求

- 批量抓 N 个商品的价格、做每日定时比价；
- 生成抢购 / 秒杀 / 刷单脚本；
- 把结果做成对外发布的比价榜单、药品广告或价格宣传；
- 抓取评价里的手机号、地址、姓名等信息。

这些都在 `SKILL.md` 的禁止清单内，Agent 应当拒绝而不是想办法实现。

## 英文触发示例

- "Compare the out-of-pocket price of ⟨product + spec⟩ across shopping apps and give me an HTML report; I'm in ⟨city⟩."
- "Find the three cheapest options and check shipping origin, courier and ETA."
